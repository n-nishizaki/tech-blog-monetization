### Phase 2: 品質チェック
5. 60%完成基準チェックリスト適用
   - [ ] 構造的完全性（STREAM揃い）
   - [ ] 証拠性（実体験ベース）
   - [ ] 最低限の品質
   - [ ] 禁止事項
   - [ ] 文字数チェック（目安±20%）
   - [ ] STREAM構造の隠蔽
6. NGなら修正、OKなら次へ

### Phase 3: 公開
7. Jekyll形式に変換（front matter設定）
8. GitHub Pagesにプッシュ
9. ビルド確認、記事URL確認

### Phase 4: 事後改善（オプション）
10. 作図追加
11. 文章磨き込み
12. SEO最適化

## ルール・制約

### コンテンツ戦略の核心原則

**「実績の発信」ではなく「思考の軌跡」を残す**

実績単体（○○をやった、○○になった）は「すごい」で終わり、信頼や依頼・購読の動機にならない。
重要なのは「抽象（問い・仮説）→ 具体（試行・失敗・修正）→ 抽象（原則化）」の軌跡を見せること。
読者に「この人はこう考える人だ」という判断基準を渡すことが、信頼構築の本質。

```
NG: 「○○をやりました」（活動報告）
OK: 「○○だと思っていたが△△だとわかった、なぜなら…」（思考の断片）
```

- 2026-02-18 学習: oh24.jp事例の分析より導出

---

### 記事作成のルール
- STREAM型フレームワークを必ず適用
- 実体験ベースの具体的な数値・エピソードを含める
- **「答え」だけでなく「どう考えたか」の思考過程を必ず含める**（抽象→具体の軌跡）
- 文字数目安の±20%以内に収める
- STREAM構造は読者に見せない（自然な見出しに変換）

### 公開基準
- 60%完成基準の全項目クリア必須
- 論理矛盾がないこと
- アフィリエイトリンクと記事内容の整合性確認

### 禁止事項
- 「〜かもしれません」「〜と思います」の多用
- 過度な煽り表現
- 根拠のない断定
- コピペ感のある定型文
