# AI観測設計

**作成日**: 2026-02-27
**位置づけ**: 市場接続戦略の補助軸（[戦略本体](../../経営企画/docs/MARKET_CONNECTION_STRATEGY.md)）

---

## 目的

**客の言語で課題を収集し、商品と記事の切り口を改善する。**

観測それ自体が目的ではない。出品ページの語彙・商品名・記事テーマに直接反映できるデータだけを集める。

---

## 原則

1. **客の言語で記録する** — 構造化・抽象化しない。投稿者の原文に近い形で残す
2. **週1回・30分以内** — これ以上かけたら観測に逃げている
3. **仮説を持って探す** — 漫然と眺めない。「今週はこの切り口を検証する」を決めてから探す
4. **出力は3つだけ** — 商品名候補、出品ページの語彙、記事テーマ候補

---

## 収集ソースと探し方

### ソース一覧

| ソース | 何を見るか | 優先度 |
|--------|-----------|--------|
| ココナラ | 競合の新着レビュー、売れ筋の変化、相談カテゴリの傾向 | 高 |
| X | 「相談できる人がいない」「何から手をつけたら」系の投稿 | 高 |
| teratail / Qiita | 技術課題の裏にあるマネジメント・判断の悩み | 中 |
| Yahoo!知恵袋 | IT転職・キャリア系の生々しい相談 | 中 |
| Google Trends | キーワードの季節変動・急上昇 | 低（月次） |

### 検索キーワードセット

検証したい仮説に応じて、以下から選んで検索する。

**IT課題・相談系**
- `IT 相談 誰に聞けばいい`
- `システム開発 何から始める`
- `オフショア開発 失敗 どうすれば`
- `AI導入 進め方 わからない`
- `ChatGPT 仕事 使えない`

**キャリア・判断系**
- `エンジニア キャリア 相談 誰`
- `転職 判断 できない`
- `PM 炎上 助けて`
- `マネジメント 限界`

**壁打ち・思考整理系**
- `壁打ち 相手 ほしい`
- `モヤモヤ 整理`
- `考えがまとまらない`
- `誰かに話を聞いてほしい IT`

**注意**: これは初期セットであり、観測結果に応じて毎週更新する。

## 分析の3軸

収集した課題投稿を以下の3軸で評価する。

| 軸 | 定義 | 評価 |
|----|------|------|
| **頻度** | 同じ種類の悩みがどのくらい出てくるか | 高/中/低 |
| **感情強度** | 投稿者の困り具合（「助けて」「限界」vs「ちょっと気になる」） | 高/中/低 |
| **未解決度** | 既存の回答・サービスで解決されているか | 未解決/部分的/解決済み |

**優先度が高い = 頻度高 × 感情強度高 × 未解決**

---

## 週次観測の流れ

```
1. 今週の検証仮説を決める（1つ）
   例:「AI導入で困っている非エンジニアの管理職は多いか？」

2. キーワードセットから2〜3個選んで検索（15分）
   → 見つけた投稿を原文のまま記録

3. 3軸で評価する（5分）
   → 頻度・感情強度・未解決度

4. アクション候補を書く（10分）
   → 商品名案 / 出品ページ改善案 / 記事テーマ案

5. 観測ログに記録
   → マーケティング/observations/YYYY-WXX.md
```

---

## 観測ログのフォーマット

ファイル: `マーケティング/observations/YYYY-WXX.md`

```markdown
# 観測ログ YYYY年 第XX週

## 今週の検証仮説
[1文で書く]

## 収集した声（原文ベース）

### 声1
- **ソース**: X / ココナラ / teratail / etc.
- **原文（要約）**: 「〜〜〜」
- **頻度**: 高/中/低
- **感情強度**: 高/中/低
- **未解決度**: 未解決/部分的/解決済み

### 声2
...

## 今週の発見
- [1〜3行で、何がわかったか]

## アクション候補
- **商品名案**: [候補があれば]
- **出品ページ改善**: [語彙の追加・変更案があれば]
- **記事テーマ案**: [候補があれば]

## 次週の検証仮説
[今週の結果を踏まえて次に探ること]
```

## 出力先と活用

| 観測で得たもの | 反映先 | 判断者 |
|---------------|--------|--------|
| 商品名候補 | 商品企画/listings/ の出品タイトル | オーナー |
| 買い手の語彙 | 出品ページの説明文 | オーナー |
| 記事テーマ候補 | コンテンツ制作の記事企画 | オーナー |
| 検証仮説の棄却/支持 | 顧客像.md の更新 | AI提案→オーナー承認 |

---

## やらないこと

- リアルタイム監視（週1回で十分）
- 網羅的な市場分析（それは `/market-research` の役割）
- 収集データの統計処理（データ量が足りない段階では意味がない）
- 観測だけで商品を変える（直接接触のデータと突き合わせてから判断）

---

## 観測設計の見直し基準

4週間（1ヶ月）実行したら以下を振り返る:

- [ ] 観測結果が実際に出品ページや記事に反映されたか
- [ ] 検索キーワードセットは適切だったか（ヒット率）
- [ ] 30分以内で完了できているか
- [ ] 直接接触（テキスト相談）のデータと整合しているか

反映実績がなければ、観測設計自体を縮小または停止する。
