# 週次AI観測コマンド

市場の課題投稿を収集し、商品・記事の切り口改善に使えるデータを集める。

## 前提

- 設計ドキュメント: `マーケティング/docs/observation-design.md`
- 過去の観測ログ: `マーケティング/observations/` を確認して文脈を引き継ぐ
- 市場調査レポート: `商品企画/docs/market-research-*.md` を参照

## 実行手順

### 1. 前回の観測ログを確認する

`マーケティング/observations/` の最新ファイルを読み、前回の「次週の検証仮説」を確認する。
初回の場合は、オーナーに今週検証したい仮説を聞く。

### 2. 検索して課題投稿を収集する

オーナーが指定した仮説（または前回からの引き継ぎ仮説）に基づき、WebSearchで以下を検索する:

**検索の方針:**
- キーワードセット（observation-design.md参照）から仮説に関連する2〜3個を選ぶ
- 各ソース（X、ココナラ、teratail、Yahoo!知恵袋等）で検索
- 見つけた投稿は**原文に近い形で**記録する（構造化・抽象化しない）

**検索例:**
- `site:twitter.com "AI導入 進め方 わからない"`
- `site:coconala.com IT相談`
- `site:teratail.com プロジェクト 炎上`

### 3. 3軸で評価する

収集した各投稿を以下で評価:
- **頻度**: 同種の悩みの出現頻度（高/中/低）
- **感情強度**: 困り具合（高/中/低）
- **未解決度**: 既存サービスで解決されているか（未解決/部分的/解決済み）

### 4. アクション候補を書く

観測結果から以下を導出:
- 商品名の候補（買い手の検索語ベース）
- 出品ページの語彙改善案
- 記事テーマの候補

### 5. 観測ログを記録する

`マーケティング/observations/YYYY-WXX.md` に記録する。
フォーマットは `マーケティング/docs/observation-design.md` の「観測ログのフォーマット」に従う。

## 原則

- **30分以内で完了する** — これ以上は観測に逃げている
- **客の言語で記録する** — 「構造化」「思考OS」は内部用語
- **仮説を持って探す** — 漫然と眺めない
- **出力は3つだけ** — 商品名候補、出品ページの語彙、記事テーマ候補
