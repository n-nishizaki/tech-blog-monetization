# blog-interview: 記事素材インタビュー

テーマ: $ARGUMENTS

## このスキルの目的

AIが作れない「実体験・具体的数値・個人の感情」を会話形式で引き出す。
質問リストの消化ではなく、**会話の流れで素材を深く掘り出す**ことを優先する。

---

## インタビューの構造

```
Phase 1: 導入（場を作る）
Phase 2: 対話インタビュー（会話優先・深さを追求）
Phase 3: 素材チェック（ヌケモレ確認）
Phase 4: 保存
```

---

## 実施ルール

### 基本姿勢
- **一度に一つの質問のみ**提示する
- 相手の回答を必ず受け取り、十分な深さが出てから次へ進む
- 事前の質問順に縛られない。会話の流れを優先する
- 感情語・転換点・具体的エピソードが出たら、その場で深掘りする

### 回答の深さの判断基準
以下が揃っていれば「十分な深さ」とみなして次へ進む。揃っていなければ深掘りを続ける。

| 素材タイプ | 十分な深さの条件 |
|-----------|----------------|
| エピソード | いつ・何をしたか・どうなったかが具体的に出ている |
| 数字 | 単位・規模・比較（before/after）が出ている |
| 感情 | どんな状況で・何を感じたかが出ている |
| 構造・洞察 | 「なぜそうなるか」の理由が出ている |

### 深掘りの技法
| 相手の発言 | 深掘りの返し方 |
|-----------|--------------|
| 抽象語（「努力した」「大変だった」） | 「具体的にどんな場面ですか？」 |
| 感情語（「嬉しかった」「悔しかった」） | 「そのときの状況をもう少し詳しく教えてください」 |
| 短い回答 | 「もう少し聞かせてもらえますか？」 |
| 数字なし | 「数字で表すとどのくらいですか？」 |
| 仮説と外れた回答 | 「実は○○だと思っていたのですが、違いましたか？」 |

---

## Phase 1: 導入

以下の文言でインタビューを始める:

```
「テーマ「$ARGUMENTS」についてインタビューします。
答えにくい質問はスキップしてOKです。
まず全体像から聞かせてください。

このテーマについて、今どんな状態ですか？」
```

回答を受け取り、話の全体像をつかんでから Phase 2 に進む。

---

## Phase 2: 対話インタビュー

導入の回答をもとに、以下のテーマを**自然な会話の順序で**カバーしていく。
順番は固定しない。話の流れで出てきたものから深掘りする。

### カバーすべきテーマ（順不同）

**[核心]**
- このテーマで一番伝えたいことは何か
- 読者がやりがちな間違いは何か
- 読者に最終的に何をしてほしいか

**[エピソード]**
- 成功体験（いつ・何をしたか・どうなったか）
- 失敗体験またはBefore（何が問題だったか・気づいたきっかけ）
- 転換点（考え方が変わった瞬間）

**[数値]**
- 具体的な数字（金額・時間・回数・期間）
- Before/Afterの比較数字
- 読者が参考にできる目安

**[構造・洞察]**
- このテーマの本質構造
- なぜ多くの人が間違えるのか
- 放置した場合のシナリオ

**[改善策]**
- 実際にやっている仕組み
- 「これだけやれば8割解決」という改善策
- 読者が最初に取れる一歩

**[収益化]**
- 紹介したいサービス・商品
- 読者が検索しそうなキーワード

---

## Phase 3: 素材チェック（ヌケモレ確認）

会話が一通り終わったら、以下のチェックリストで**記事に必要な素材が揃っているか**確認する。

```
「ここまでの内容を整理します。

✅ 揃っているもの:
[出てきた素材を列挙]

⚠️ まだ薄いもの:
[深さが足りない素材を列挙]

❌ 出ていないもの:
[カバーできていないテーマを列挙]
```

**必須素材**（これがないと記事が成立しない）:
- [ ] 核心メッセージ（一言で言えるか）
- [ ] 具体的なエピソード（成功 or 失敗のどちらか）
- [ ] 数字（最低1つ以上）

**あると記事の質が上がる素材**:
- [ ] Before/Afterの対比
- [ ] 転換点のエピソード
- [ ] 構造的な洞察（なぜそうなるか）
- [ ] 読者向けの具体的な改善策

⚠️ の項目と ❌ の項目について、追加で質問して素材を補う。

補完が終わったら確認する:
```
「これで素材は揃いました。まとめて確認します。

[核心・エピソード・数字の要約]

この理解で合っていますか？補足があれば教えてください。」
```

---

## Phase 4: 保存

確認が取れたら以下の形式で保存する。

**保存先**: `コンテンツ制作/interviews/[記事番号]-[テーマスラッグ]-interview.md`

```markdown
---
テーマ: [テーマ名]
ヒアリング日: [日付]
記事番号: article-[XX]
---

# インタビュー記録: [テーマ名]

## 核心メッセージ
[回答]

## よくある間違い
[回答]

## 読者への期待アクション
[回答]

## 実体験・エピソード
### 成功体験
[回答]

### 失敗体験・Before
[回答]

### 転換点
[回答]

## 数値・データ
[回答]

## 構造的洞察
### 本質構造
[回答]

### なぜ間違いが起きるか
[回答]

### 放置した場合の損失
[回答]

## 改善策・仕組み
[回答]

## SEO・収益化
### 紹介サービス
[回答]

### キーワード候補
[回答]
```

保存完了後:
```
## インタビュー完了

保存先: コンテンツ制作/interviews/[ファイル名]

次のステップ:
/blog-structure [テーマ名] でSTREAM構成案を作成してください。
```
