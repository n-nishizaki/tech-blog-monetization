# 市場接続戦略 — 外部接触量の構造的解決

**策定日**: 2026-02-27
**ステータス**: 承認待ち

---

## 現状の診断

内部分析は十分。外部接触量が圧倒的に不足している。

- **強み**: 構造化・解決設計（パターン認識、言語化）
- **弱み**: 課題発見・顧客獲得（①の不足）
- **対策**: AIで弱みを補い、強みに集中する構造を作る

---

## 活動の基本構造

```
AI（市場観測・課題言語収集）
  × Norio（構造化・解決設計）
  → テキスト相談で検証
  → 再現性の高い課題を有料ノート化
```

---

## 2つの市場接続（並行運用）

### 1. 直接接触（主）

テキスト相談を週次で出す。

| 項目 | 内容 |
|------|------|
| チャネル | ココナラ（テキスト相談） |
| 完成度 | **30%で出す**（内部作業を意図的に下げる） |
| 位置づけ | 「仮説検証001」として扱う。納品物と自己評価を切り離す |
| 取得データ | 客が使った言語、反応した切り口、言語化されていない悩み |
| 頻度 | 週次で出品・更新 |

### 2. AI観測（補助）

X・専門フォーラム等から課題投稿を収集・分類する。

| 項目 | 内容 |
|------|------|
| 収集対象 | X、専門フォーラム、ココナラの相談傾向 |
| 収集の姿勢 | 「構造化」ではなく**客の言語で**課題を収集する |
| 優先順位づけ | 頻度・感情強度・未解決度の3軸 |
| 活用 | 商品名の候補、出品ページの語彙、記事テーマの選定 |

### 2つの接続の関係

```
観測で仮説を立てる → 相談で検証する → 客の言語が返る → 観測設計を更新する
```

別物ではなく、**同じサイクルの入口と出口**。

---

## 優先順位

| 順序 | 行動 | 理由 |
|------|------|------|
| 今すぐ | テキスト相談を出し続ける | 外部接触が最優先。完成度30%でいい |
| 並行 | 観測設計を作り週次で仮説を更新する | 相談の質を上げる補助 |
| 後で | 再現性の高い課題を有料ノート化 | 十分なデータが溜まってから |
| 最後 | ブログは商品の裏付けとして積み上げる | 信頼構築の土台。急がない |

---

## 行動原則

1. **出す前の内部作業を意図的に下げる** — 準備で消耗しない
2. **うまくいかなかったら仮説棄却として次へ** — 失敗ではなくデータ
3. **観測設計は補助であって主役ではない** — 観測に逃げない
4. **前提を疑うために「次の罠を先に列挙する」を習慣化する** — 自分の思考バイアスを先回りで潰す

---

## 「反応を見る」で得られるデータ（50%の根拠）

購入に至らなくても、以下のシグナルで市場の反応は取れる。

| シグナル | わかること |
|---------|-----------|
| ページ閲覧数 | そもそも需要があるか |
| お気に入り登録 | 「気になる」レベルの関心 |
| 問い合わせ内容 | 何に困っているかの生データ |
| 類似商品の売れ筋 | 市場が何に金を払っているか |

残りの50%（相手の本当の悩み、自分がどこで価値を出せるか、納品フォーマットの検証）は**2〜3件の実際の受注**で取る。

---

## レバレッジ設計（将来）

```
Phase A: 反応を見る（出品して観察）
  → 閲覧・お気に入り・問い合わせを観察
  → ブログ記事の反応も並行で見る
  → 「どの切り口が刺さるか」を掴む

Phase B: 少数だけ受ける（2〜3件）
  → 実際の対話で「言語化されていない悩み」を拾う
  → 自分の強みがどこで効くかを確認する

Phase C: パターン化してレバレッジ商品に変換
  → Phase A+Bで得たデータを使って型化
  → 再現性の高い課題を有料ノート化
```

---

## この戦略の前提（疑うべきポイント）

- 「テキスト相談を出し続ける」が実行できるか（出品更新の心理的ハードル）
- AI観測の精度が十分かどうか（ノイズが多すぎて使えない可能性）
- 30%完成度で出して信頼を損なわないか（プラットフォームの評価制度との兼ね合い）
- 「反応データ」と「購買意欲」の間にギャップがないか
